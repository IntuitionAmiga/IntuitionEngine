Shared bus machine

Six CPU views, one bus.

Intuition Engine is built around MachineBus: a shared memory and MMIO backplane for six CPU views, six video systems, ten audio engines and coprocessor workers.

Six CPU views, one bus

CPU profiles choose the instruction set, loader, and RAM ceiling. After boot, code uses MachineBus RAM, SYSINFO, MMIO devices, video and audio engines, files, debug state, and coprocessor services.

MachineBus

RAM sizing for guest code

Backing size, total guest RAM, active RAM, low-window bounds, and profile ceilings live on the bus. SYSINFO publishes those values; IE64 also reads CR_RAM_SIZE_BYTES.

CPU views

CPU view matrix

IE64 uses wide registers. IE32 uses fixed-width RISC code. 6502 and Z80 use banked and mapped views, while M68K and x86 keep their own address models.

Runtime services as address ranges

Bus address ranges cover file I/O, media load, Program Executor, terminal and input devices, CPU wait, Voodoo apertures, Bootstrap HostFS, and SYSINFO.

EmuTOS, AROS, and IntuitionOS boot through different loaders. Their verified graphics, input, file, MIDI, and audio routes write to MMIO registers and mapped bus memory, then use the relevant interrupt and device-state paths.

EmuTOS gets a hardware-accelerated IE VideoChip driver through the IE target. The implementation runs 640 x 480 RGBA direct VRAM, uses the VideoChip blitter for accelerated drawing, reads keyboard and mouse MMIO, and drives timer IRQ level 5 and VBlank IRQ level 4.

AROS graphics and filesystem

AROS graphics target

AROS maps a 64 MiB VideoChip VRAM slice and supports big-endian VideoChip reads. IE64 graphics grants

hardware.resource owns the CHIP page and VRAM grant policy. MIDI split

Live MIDI by profile

Raw byte-stream registers for live MIDI sit at 0xF0BF4-0xF0BF6. EmuTOS uses an output-only MC6850 ACIA shim at $FFFC04 and $FFFC06, feeding the live-MIDI parser. AROS has an ie-m68k CAMD path. The current source tree has no IntuitionOS MIDI driver path.

A CPU can be a device for another CPU

Coprocessor MMIO starts IE32, IE64, 6502, M68K, Z80, or x86 cores as bus workers. A caller queues a request and polls or waits on a ticket. BASIC has named entry points; assembly and C can write to the coprocessor MMIO block and mailbox rings directly.

Native synth voices

Native audio uses ten FLEX voices and 32 SFX channels. FLEX gives each voice frequency, volume, gate/control, ADSR, waveform select, PWM, ring modulation, hard sync, and signed 8-bit DAC input. Oscillators cover square/pulse, triangle, sine, noise, and sawtooth modes.

Clocking and samples

Separate chip clocks

Whole-machine debugging

IE Mon can stop the machine, inspect CPU and bus state, and restore retained snapshots. Snapshot coverage includes registered CPUs, bus RAM, sparse backing pages, and versioned device blobs.

Reverse history

IE Mon stores CPU-local step history and whole-machine reverse snapshots. Whole-machine restore reports device failures instead of continuing with half-restored state.

IE Mon PDF

Observability

IE_PERF_ACCT=1 turns on CPU timing, retired instruction counts, subsystem buckets, and JIT deopt reason accounting. When the flag is off, the hot path exits before atomic work.

IE64 above low memory

IE64 keeps 64-bit PC, data, and stack state. JIT helper exits route high physical addresses and MMU translations through interpreter-equivalent helpers, then resume only when architectural state still matches.

IE64 ISA PDF

Lifecycle

Reset and load routines quiesce scripts, render loops, media, CPUs, EmuTOS, and AROS. Afterwards they rebuild CPU/profile state, rewire the monitor and Program Executor, and reload configured coprocessor services.

Timing

CPU execution, the 60 Hz compositor, and the 44.1 kHz audio mixer run on separate cadences. Published bus maps, retained video leases, and triple-buffer handoff avoid unnecessary copies in hot loops.

Monitor and script state

IE Mon and IEScript

IE Mon at hardware level

From a frozen machine, the monitor switches CPU focus, edits registers and memory, sets breakpoints and watchpoints, shows I/O register groups, and walks reverse history across the six CPU families and coprocessor workers.

Execution control

CPU state, live

IE Mon switches focus between registered CPUs, changes registers, disassembles expressions such as pc+$20, interleaves source locations when available, single-steps, continues, and assembles one IE64 instruction at an address.

cpu
r
d /s pc 8
b main+0x10 if R1==$10 && hitcount>2
s
g
Bus diagnosis

Memory and MMIO traces

SoftICE-style bpm* watchpoints cover byte, word, long, and quad accesses in read, write, or read/write mode. Page guards, access logs, who, bfirst, and trace mmio identify bus activity from recorded access data.

bpmqw $f0000
pg add $f0000 $f0fff rw cpu=current
accesslog on 1024
who wrote $f0004
trace mmio mmio 16
Reverse history

Back through snapshots

rs restores the focussed CPU from local step history. rg, rt, tl, and history horizon use retained whole-machine snapshots for registered CPUs, bus RAM, sparse IE64 backing pages, and versioned device blobs.

history horizon
tl 12
rg
rt PC==$2000
ss checkpoint.ie64state
sl checkpoint.ie64state

Monitor API

With dbg, scripts open the monitor, step or continue execution, set breakpoints and watchpoints, read registers and memory, disassemble, inspect I/O views, and snapshot registered devices. Raw RAM access requires an explicit freeze; MMIO access does not.

IE64 BASIC build modes

IE64 BASIC runs on the IE64 CPU and stores programmes through the machine File I/O block. Stored lines can run through the interpreter, AOT compiler, standalone image writer, assembly text path, or in-machine assembler. Typed BASIC also writes to MMIO, waits for video, drives blitter modes, starts music, and calls coprocessor workers.

Path What BASIC does Hardware or file interface
Stored programme LOAD, SAVE, BLOAD, DIR, and TYPE use the machine disk volume. BLOAD puts raw assets into guest memory. File I/O MMIO, including IE64 FILE_DATA_PTR64.
Native execution RUN AOT compiles the stored programme to native IE64 code inside the machine and runs it immediately. IE64 AOT mode, matching the visible result contract of RUN.
Standalone image COMPILE "DEMO" writes DEMO.ie64 and a matching IE64 assembly listing. Flat IE64 image plus self-contained assembly text.
Assembly round-trip TRANSPILE writes IE64 source only; ASSEMBLE reads IE64 source and writes a standalone .ie64. In-machine assembler at PROG_START.
Device control PEEK8/16/32/64, POKE8/16/32/64, WAIT, VSYNC, BLIT MODE7, and the direct sound commands. MMIO registers for video, blitter, audio, media loader, and timing.
Worker CPUs COSTART, COCALL, COSTATUS, COWAIT, and COSTOP call the coprocessor service block. Shared coprocessor MMIO and mailbox rings.

Native commands

COMPILE rejects direct-mode-only commands and stored forms unsupported by standalone images. Use TRANSPILE for inspection. ASSEMBLE reads IE64 source from the disk volume and emits a flat image.
